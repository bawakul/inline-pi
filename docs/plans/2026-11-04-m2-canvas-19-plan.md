# M2: Canvas replies never land (#19) — implementation plan

**Repo:** `inline-pi` (Obsidian plugin) · **Date:** 2026-11-04 · **Status:** plan (main-session), awaiting walkthrough gate before build
**Companion plans:** `2026-11-04-m2-queue-plan.md` (#20 + #29 — Commit A/B/C/D sequence there)

## 1. Diagnosis (confirmed from source)

- Trigger side works: `prepareCanvasCallout` (src/canvas-trigger.ts) resolves the node id, writes the pending callout via the node's editor, saves the file, enqueues the prompt with `Node ID: …` appended.
- Settle side is broken: `onSettle: (result) => handle.onSettle(result)` routes into the `CalloutHandle`, which replaces the callout through the **trigger-time editor instance**. A canvas node's editor is created on focus and destroyed on blur; by settle time it's detached, so `findCalloutBlock` misses and `replaceWithCallout` **silently returns**. (Silent return verified in `callout-streaming.ts` `replaceWithCallout`.)
- The purpose-built write path — `deliverCanvasReply` / `writeCanvasReply` / `patchCanvasJson` (src/canvas.ts, node-ID-first `setData` + `requestSave`, atomic `vault.process` JSON-patch fallback for closed leaves, tested in `src/__tests__/canvas.test.ts`) — is imported by `canvas-trigger.ts` but **never called**.

## 2. Changes

1. **Reroute the canvas settle path** (`prepareCanvasCallout`): in `onSettle`, build the final callout text and call `deliverCanvasReply(app, filePath, nodeId, query, response)` instead of `handle.onSettle(result)`:
   - green → `buildResponseCallout(query, finalContent)`
   - error/aborted → `buildErrorCallout(query, errorMessage)`
   - `deliverCanvasReply` already handles: leaf open → canvas API by node id (query-text fallback); leaf closed → atomic JSON patch. Always prefer it over the editor handle for canvas — it works whether or not the editor survived.
   - If delivery fails (`ok: false`), do not evaporate: `console.warn` + Obsidian `Notice` ("couldn't place the answer in the canvas node").
2. **Make markdown failure loud too** (`callout-streaming.ts` `replaceWithCallout`): replace the silent `return` on `findCalloutBlock` miss with `console.warn` + `Notice`. Same bug class — silence hid this for two weeks.
3. **Keep the abort wiring as-is** (`wireAbort` on the handle) — it doesn't depend on the editor surviving.

## 3. Sequencing / interactions

This plan's reroute pattern is the template: queued/active visual flips in canvas should also go through the canvas write path, not the editor handle. Fold into #19's implementation or a tight follow-up; do not ship Commit C for canvas against the editor handle.
